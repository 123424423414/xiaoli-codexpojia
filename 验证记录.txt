3. 自检发现并修复的缺陷（诚实记录）
-----------------------------------
自检第一次运行 44 项中 3 项失败，其中 2 项是产品代码缺陷、1 项是自检脚本自身的赋值错误：

  a) Windows 进程存活探测错误（已修）
     OpenProcess 对「已终止但句柄尚未全部释放」的进程仍会返回有效句柄，
     旧实现据此判定进程存活，导致崩溃残留锁永远无法用 --break-lock 接管。
     修复：改用 GetExitCodeProcess + STILL_ACTIVE(259) 判定，并显式声明
     WinDLL 的 restype/argtypes（顺带修掉 64 位句柄被 ctypes 默认 c_int 截断的隐患）。
     回归测试：tests/test_engine.py::test_pid_alive_detects_exited_process。
  b) --verify 失败时明细丢失（已修）
     verify 的 ok=False 语义（「有检查项未通过」）被当成「执行失败」，
     明细不打印、stderr 只输出「执行未完成：None」。
     修复：verify 分支先于失败分支处理，检查明细与结论一律走 stdout，退出码仍为 1。
     回归测试：tests/test_cli.py::test_verify_failure_prints_checks_to_stdout。
  c) 行内尾注释被覆盖（已修）
     定点替换整行时原实现会丢掉该行的行尾注释。修复：词法扫描记录尾注释并原样写回。
     回归样例：selfcheck A13 / A14。
  d) 损坏产物导致校验抛栈（已修）
     产物被破坏到 deflate 层时，zipfile 抛的是 zlib.error 而不是 BadZipFile，
     原实现的异常白名单漏掉它，校验会以异常栈结束而不是给出结构化问题。
     修复：校验内部一律把异常转成 problems 列表（自检 E2 现在稳定报出「产物无法完整校验」）。
  e) 批处理文件的编码问题（已修，Windows 专项）
     用 UTF-8 保存的 .cmd 被 cmd.exe 按系统代码页（GBK）逐字节解析，中文字节错位后
     会咬掉引号配对，脚本从 `set "HERE=%~dp0"` 起整体崩坏
     （现象：`'~dp0"' is not recognized`、`else was unexpected at this time`）。
     修复：四个 .cmd 改为**纯 ASCII**（提示改英文；EXE 用 `for %%F in ("%HERE%*.exe")`
     发现而不是硬编码中文文件名），并在 selfcheck E6 加断言防回归。
  f) 批处理文件的换行问题（已修，Windows 专项）
     .cmd 里 `goto :标签` 的标签查找依赖 CRLF；文件是 LF-only 时 cmd 报
     `The system cannot find the batch label specified - done`，脚本继续往下跑，
     把 EXE 分支的退出码污染成 1（预期 2）。
     修复：源文件转 CRLF；打包器对 .cmd/.bat 强制 CRLF、对 .sh/.command 强制 LF；
     selfcheck E6/E8 断言源文件与产物内的换行都正确。

3.5 测试自身的稳定性问题（已修）
--------------------------------
  单元回归出现过一次随机失败：test_pid_alive_detects_exited_process 依赖「刚退出的进程」这一前提，
  而同机大量起 Python 进程时该 pid 会被系统立刻复用，结论随之翻转。
  修复：改为两条确定性断言（当前进程必定存活、一个不可能存在的 pid 必定判定为不存在），
  「刚退出」这条改为最多重试 5 次、只要一次判定为已退出即通过；连跑三次均为 OK。
  这类随机失败会掩盖真实回归，因此按缺陷处理而不是重跑了事。

3.6 独立审查（另一个代理，独立视角）发现的问题与处置
----------------------------------------------------
用独立子代理对代码做对抗性审查（它不读真实 .codex 内容，实验全在临时目录）。共报 5 条 + 3 条低危，
逐条自己复现后全部确认属实，处置如下：

  H1【高】注入键被静默写进错误的表（真实缺陷，已修）
     触发：活动 profile 段后面还有子表（例如 Codex 真实的 `[profiles.work.mcp]`）时用 --target profile 注入。
     旧 `_segment_end()` 用 `len(header.keys) <= len(table)` 判段边界，把子表头跳过，
     键被插到子表乃至文件末尾；而旧 `_without()` 会整棵删掉顶层节点，导致
     「写前语义等价断言」在 profiles 子树内完全失效——于是 install 报 ok、后续 status/verify/restore 全乱。
     修复：段边界改为「第一个后续表头」；`_without()` 改为只删目标叶子（并支持数组表 [[items]]）。
     回归：tests/test_toml.py 四条 + selfcheck H1 端到端（install→status→verify→restore 全绿）。
     注：修复过程中我的第一版改法（跳过所有子表头）同样是错的，是强化后的 `_verified()` 当场拦下写入才暴露。

  M1【中】管理块之后被追加内容会让 --install 永久失败（已修）
     旧 `compose()` 直接抛「管理块之后还有手动内容」，engine 里「另建副本保留手工改动」的分支永远走不到。
     修复：这些内容改为并入正文（移动到身份块之前），零丢失，并在 warnings 里报告 relocated_tail_lines。
  M2/M5【中】恢复与损坏后的可观测性缺口（已修）
     restore 保留的手工副本、残留工具目录在 doctor 里显示「未安装/正常」；状态文件损坏时 doctor 唯一的建议
     是再跑一次 --status（死循环）。修复：doctor 新增「存在残留工具目录但没有安装状态」场景并列出残留文件；
     状态损坏时给出可行路径（改名保留现场后重装）并列出目录内文件。
  M3【中】--break-lock 对「活 pid 的锁」无效，文案与行为矛盾（已修）

3.9 进入实际使用阶段后暴露的问题（已修）
----------------------------------------
  a) .cmd 的 pause 会永久挂起（真实故障，本轮在系统里抓到实例）
     不带参数被 `cmd /c` 调用时没有可交互的 stdin，`pause` 会让进程永远卡住。
     系统里实际发现 4 个这样的挂起 cmd（启动/状态/检查三个脚本）与 2 个 10:32、10:34 遗留的 python，
     还占着两个临时日志文件；已全部清理。
     修复：`pause` 改为 `timeout /t 60`（双击时等 60 秒供阅读；非交互时 timeout 立即失败并继续）。
     实测：非交互、不带参数调用，0.3 秒返回、退出码 2，不再挂起。
  b) 并发首次安装的目录创建竞态（偶发真实缺陷）
     Windows 上两个进程同时 `mkdir(parents=True, exist_ok=True)` 仍可能抛 FileExistsError，
     导致双进程同时首次安装时两个都失败（自检 B4 抓到过一次 [2,2]）。
     修复：新增 `_ensure_dir` 吸收该竞态；新增「4 进程并发首次安装」回归测试。
  c) 检测脚本与用户配置耦合（测试隔离缺陷）
     单元测试与 selfcheck 原先会读取仓库里的 profile.json，用户一改口令（本轮真发生）测试就变红。
     修复：两者改用各自的隔离 profile；selfcheck 的口令断言改为与文案无关（只校验两行 + 恰好 4 个半角空格）。
  d) 环境检测把合法安装目录误判为残留
     真实环境接管后，`.codex\managed-prompts\xiaoli-armor` 被计入了「用户目录残留」。
     修复：该项改为按安装状态报告（已安装 → 校验引用一致），残留清单只保留真正不该出现的路径。
